# 專案企劃：AI 逆轉法庭：證詞的破綻

## 專案目標

使用生成式 AI 與固定規則，製作一款可透過網址分享、在瀏覽器遊玩的視覺化法庭推理遊戲。玩家扮演辯護律師，從證人說法和案件證據中找出矛盾。

## 已確認的 MVP

| 項目 | 規劃 |
| --- | --- |
| 案件 | 一個虛構的美術館怪談與拍賣前失畫案「霧港館的第六個人」 |
| 玩家 | 被告辯護律師 |
| 視覺素材 | `assets/` 內含 2 張場景圖（美術館 B 展廳、法庭）、3 張證人立繪、5 張證物特寫圖 |
| 證人 | 三位，個性、所在位置、立繪頭像與所知資訊不同，並提供快捷追問問題（部分需先讀過相關證物才解鎖） |
| 證據 | 五項，對應 2D 現場五個不預先劇透名稱的可互動現場物件（入口旁電腦螢幕、牆面警報控制面板、長椅上的勤務簿、桌上的出庫單文件夾、中央畫框與檢驗報告），點擊後進入第一人稱近距離檢視看板／拿起報告畫面，由玩家自行點擊可疑紀錄採證收進證物袋並在庭上出示 |
| 互動 | 現場點擊物件、翻閱報告看板採證與快捷追問皆不呼叫 API；只有自由輸入會呼叫 Gemini。庭上反應也使用固定台詞。固定台詞每個主題有多句，隨機挑選且不連續重複 |
| 推理 | 玩家先配對四個案發時間，再判讀 E3/E4 證據範圍，最後於左右對決介面選擇證詞和證物；Python 依固定答案驗證 |
| 狀態 | 每位玩家的對話、證據與進度彼此獨立 |
| 結局 | 包含成功揭露真相與未能證明案件兩種結果，搭配法庭視覺畫面 |

## 一局遊戲流程

0. **漫畫式序章**：開始遊玩前逐格閱讀四格開場，交代第六個人影怪談、原畫遭調包、清潔員被指控與拍賣目錄上的署名疑點；可逐格翻頁或跳過，不先揭露犯人與真相。
1. **現場探索與案件卷宗**：在大型 2D 美術館調查空間（`assets/scene_museum.jpg`，支援「🖥️ 全螢幕沉浸模式」與手電筒微光探索）尋找並點擊 5 個現場可疑物件，進入第一人稱近距離看板／手持報告畫面並點選關鍵疑點收進證物袋；時間軸上與證物相關的事件及證人快捷追問，要親自採集該證物後才會解鎖。
2. **詢問證人**：在立繪詢問室點選快捷追問（固定台詞）或自由輸入問題（使用 Gemini），從回答中尋找需要追問的說法。
3. **時間線推理**：將 18:41 警報旁路開始、18:42 策展人進入、18:54 警報恢復、18:56 運輸箱出館配到正確時間；再判斷 E3 勤務簿和 E4 出庫單的證據範圍。Python 固定答案，錯誤不會直接判敗，逐步提示可協助卡關玩家。
4. **證據攻防**：在左右對決介面選擇證詞並出示證物；Python 檢查這組證詞與證物是否矛盾，再更新遊戲進度。答錯時逐步給提示，第三級揭示正確配對但不判敗；成立矛盾後顯示預先撰寫的證人反應，不消耗 Gemini 額度。
5. **最後推理**：確認完成檢查表後，玩家看著嫌疑人立繪提出最後推理，進入相應結局。結案推理要綜合各項紀錄，不能把空白箱內物品欄當成已直接證明真跡在箱內。

## 技術分工

| 元件 | 職責 |
| --- | --- |
| Python (`game_data.py`) | 固定案件資料、時間軸、圖片路徑、證據驗證、回合與結局規則 |
| Streamlit (`app.py`) | 視覺化瀏覽器介面、五階段引導、玩家工作階段、部署入口 |
| Gemini API (`ai_dialogue.py`) | 依已知角色設定回應玩家自由輸入的問題 |
| GitHub | 保存程式、美術插圖（`assets/`）與供其他 AI 閱讀的企劃文件 |
| Streamlit Community Cloud | 預定的免費公開網站部署平台 |

## 安全與額度控制

- Gemini API Key 僅存於 Streamlit 部署 Secrets；公開 GitHub 儲存庫不得包含金鑰。
- 限制單次輸入長度及每局 AI 呼叫數，避免免費額度快速耗盡。
- API 失敗或額度用盡時，以固定角色回應維持遊戲可玩性。
- 遊戲採虛構案件；不收集玩家個人資料。
- 使用玩家自己的 Streamlit 工作階段保存狀態，不把一位玩家的資料提供給其他玩家。

## 第一版案件設定

拍賣預展開幕前一晚，《海霧港灣》原作不見了，畫框裡只留下修復室編號 R-07 的仿作。閉館後，展廳玻璃裡又浮出「第六個人」；清潔員王冠宇早在三晚前便把這道影子記進勤務簿，卻因當晚仍在館內而成為嫌疑人。策展人林書妍說自己沒進過展廳，保全陳建中也堅稱警報正常，但門禁影像和控制台紀錄讓兩人的說法都出現裂縫。

追查紫外線底片後，玩家發現原作清漆下藏著一名女子和被覆蓋的署名「林月琴」；館藏卡及隔日拍賣目錄卻只列知名畫家沈景川。林月琴是林書妍的外祖母。她在警報旁路期間進入展廳，之後簽核一只貨物欄空白、複寫聯卻指向林月琴舊畫室的恆溫箱。真相不是鬼影作祟：那道人影來自被抹去的作者，而原畫被移走，是為阻止署名在拍賣前再度消失。玩家必須把門禁、警報、舊筆記、物流單與仿作鑑定串起來；單一證物都不足以直接證明整件事。

兩組可驗證的矛盾已固定：

| 證詞 | 正確證物 | 判定 |
| --- | --- | --- |
| 策展人說閉館後沒有進入 B 展廳 | E1 門禁與入口影像紀錄 | 18:42 入口影像核對為策展人本人進入 B 展廳 |
| 保全說警報沒有被解除 | E2 警報控制台紀錄 | 18:41 至 18:54 感應器被切換為旁路 |

玩家需閱讀五項證物、完成時間線配對與兩項證據範圍判讀、找出兩組矛盾，最後指出林書妍移走並調包原畫，將原作送往林月琴舊畫室，藉此阻止拍賣目錄抹去署名。時間線和證據範圍題可不限次重試並逐步取得提示；法庭出示錯誤時會逐步提示，第三級揭示配對答案，玩家仍可繼續。錯誤結案仍會進入失敗結局。全部案件資料與判定規則位於 `game_data.py`。

## AI 與免費額度

預設模型為 Gemini 3.5 Flash-Lite。快捷追問和庭上反應使用固定台詞，不消耗 API 額度；每個玩家工作階段最多可送出 8 次自由提問，同一個 Streamlit 程序每天最多呼叫 100 次。後者是程序內的保護上限，服務重啟後會重設；若擴增成多程序部署，需改用共享儲存才能形成全站共用上限。啟用 Gemini 時只會送出玩家自由輸入的問題、該名證人的公開設定和近期對話紀錄，不會傳送完整案件解答或其他玩家資料。Google 免費層可用模型、資料處理方式與額度可能變動，請查看 [Gemini API 官方定價頁](https://ai.google.dev/gemini-api/docs/pricing)。

## 建議開發順序

1. 完成不需 API Key 也能從頭玩到結局的規則與視覺化版本。
2. 設定 Gemini API Key，試玩 AI 角色對話與固定備援回應。
3. 從 GitHub 部署至 Streamlit Community Cloud，設定伺服器端 Secrets。
4. 用公開網址確認不同玩家的工作階段互相獨立。
