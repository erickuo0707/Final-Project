# 專案企劃：AI 逆轉法庭：證詞的破綻

## 專案目標

使用生成式 AI 與固定規則，製作一款可透過網址分享、在瀏覽器遊玩的視覺化法庭推理遊戲。玩家扮演辯護律師，從證人說法和案件證據中找出矛盾。

## 已確認的 MVP

| 項目 | 規劃 |
| --- | --- |
| 案件 | 一個虛構的美術館名畫失竊案，暫名「消失的名畫」 |
| 玩家 | 被告辯護律師 |
| 視覺素材 | `assets/` 內含 2 張場景圖（美術館 B 展廳、法庭）、3 張證人立繪、5 張證物特寫圖 |
| 證人 | 三位，個性、所在位置、立繪頭像與所知資訊不同，並提供快捷追問問題（部分需先讀過相關證物才解鎖） |
| 證據 | 五項，附帶視覺插圖、時間地點標籤與中性類別標籤（不提示哪項是關鍵證物），玩家可查看並在庭上出示 |
| 互動 | 玩家可點選快捷追問或自由提問；AI 扮演證人及法庭角色回應。與本案無關的問題，證人會表示無關並拉回案情；備援台詞每個主題有多句，隨機挑選且不連續重複 |
| 推理 | 玩家於左右對決介面選擇一段證詞和一項證據；Python 依固定答案驗證矛盾 |
| 狀態 | 每位玩家的對話、證據與進度彼此獨立 |
| 結局 | 包含成功揭露真相與未能證明案件兩種結果，搭配法庭視覺畫面 |

## 一局遊戲流程

1. **案件卷宗**：透過美術館現場插圖、案發當晚時間軸與樓層配置理解背景，並將 5 項圖文證物加入筆記；時間軸上與證物相關的事件，要讀過該證物才會解鎖。
2. **詢問證人**：在立繪詢問室點選快捷追問或自由輸入問題，從回答中尋找需要追問的說法。
3. **證據攻防**：在左右對決介面選擇證詞並出示證物；Python 檢查這組證詞與證物是否矛盾，再更新遊戲進度。
4. **AI 即時反應**：AI 依程式提供的結果生成角色反應（無 API Key 時使用固定備援反應）。
5. **最後推理**：確認完成檢查表後，玩家看著嫌疑人立繪提出最後推理，進入相應結局。

## 技術分工

| 元件 | 職責 |
| --- | --- |
| Python (`game_data.py`) | 固定案件資料、時間軸、圖片路徑、證據驗證、回合與結局規則 |
| Streamlit (`app.py`) | 視覺化瀏覽器介面、四步驟引導、玩家工作階段、部署入口 |
| Gemini API (`ai_dialogue.py`) | 依已知角色設定和程式驗證結果生成對話 |
| GitHub | 保存程式、美術插圖（`assets/`）與供其他 AI 閱讀的企劃文件 |
| Streamlit Community Cloud | 預定的免費公開網站部署平台 |

## 安全與額度控制

- Gemini API Key 僅存於 Streamlit 部署 Secrets；公開 GitHub 儲存庫不得包含金鑰。
- 限制單次輸入長度及每局 AI 呼叫數，避免免費額度快速耗盡。
- API 失敗或額度用盡時，以固定角色回應維持遊戲可玩性。
- 遊戲採虛構案件；不收集玩家個人資料。
- 使用玩家自己的 Streamlit 工作階段保存狀態，不把一位玩家的資料提供給其他玩家。

## 第一版案件設定

案發於市立霧港美術館。《海霧港灣》在閉館後被仿作替換，清潔員王冠宇因當晚仍在館內而遭懷疑。策展人林書妍的識別證於 18:42 進入 B 展廳；警報在 18:41 至 18:54 被她的管理帳號切換為旁路；18:56 她簽核的恆溫運輸箱由西側出館。畫框中的畫作經鑑定為仿作。清潔勤務紀錄則顯示王冠宇在 B1 器材室工作。

兩組可驗證的矛盾已固定：

| 證詞 | 正確證物 | 判定 |
| --- | --- | --- |
| 策展人說閉館後沒有進入 B 展廳 | E1 門禁與入口影像紀錄 | 18:42 入口影像核對為策展人本人進入 B 展廳 |
| 保全說警報沒有被解除 | E2 警報控制台紀錄 | 18:41 至 18:54 感應器被切換為旁路 |

玩家需閱讀五項證物、找出兩組矛盾，最後指控策展人並選出完整證據鏈，才能取得成功結局。三次錯誤出示或錯誤結案會進入失敗結局。全部案件資料與判定規則位於 `game_data.py`。

## AI 與免費額度

預設模型為 Gemini 3.5 Flash，未設定 Key 時使用固定備援對話。每個玩家工作階段最多呼叫 8 次；同一個 Streamlit 程序每天最多 100 次。後者是程序內的保護上限，服務重啟後會重設；若擴增成多程序部署，需改用共享儲存才能形成全站共用上限。啟用 Gemini 時會送出玩家問題、該名證人的公開設定和近期對話紀錄，不會傳送完整案件解答或其他玩家資料。Google 免費層可用模型、資料處理方式與額度可能變動，請查看 [Gemini API 官方定價頁](https://ai.google.dev/gemini-api/docs/pricing)。

## 建議開發順序

1. 完成不需 API Key 也能從頭玩到結局的規則與視覺化版本。
2. 設定 Gemini API Key，試玩 AI 角色對話與固定備援回應。
3. 從 GitHub 部署至 Streamlit Community Cloud，設定伺服器端 Secrets。
4. 用公開網址確認不同玩家的工作階段互相獨立。
